# План: Система управления пользователями

## Краткое описание

Замена привязки к одному Telegram ID на полноценную систему пользователей с ролями, правами, приглашениями и веб-интерфейсом управления.

## 2. API эндпоинты

**Файл:** `hik-telegram-bot/app/main.py`

### Админские (только owner)

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/api/admin/users` | Список пользователей |
| PUT | `/api/admin/users/{id}` | Обновить права |
| DELETE | `/api/admin/users/{id}` | Деактивировать |
| POST | `/api/admin/invite` | Создать приглашение |
| GET | `/api/admin/invites` | Список приглашений |
| DELETE | `/api/admin/invites/{id}` | Отозвать |
| GET | `/api/admin/audit` | Лог действий |

### Общие (с проверкой прав)

| Метод | Путь | Изменения |
|-------|------|-----------|
| GET | `/api/telegram/check` | Добавить role, permissions |
| POST | `/api/door/open` | **Добавить проверку can_open_door** |

### Авторизация админских эндпоинтов

Telegram WebApp `initData` HMAC валидация через `BOT_TOKEN`. Стандартный паттерн Telegram Mini Apps.

## 3. Изменения в боте

**Файл:** `hik-telegram-bot/app/bot.py`

### `/start invite_<token>`

Новый flow для приглашений:
1. Проверить токен (существует, не использован, не истёк)
2. Создать пользователя из приглашения
3. Пометить приглашение как использованное
4. Ответить приветствие с правами

### Новые команды

| Команда | Описание |
|---------|----------|
| `/admin` | Ссылка на панель управления (только owner) |
| `/status` | Показать свои права |

### Уведомления — broadcast

Вместо одного владельца → **все активные пользователи** с `receive_notifications=1` для данной квартиры.

Каждый получает свой callback с проверкой `can_open_door`.

## 4. Веб-интерфейс

**Файл:** `hik-web/settings.html` (НОВЫЙ)

### Структура

- Vanilla HTML/CSS/JS (без фреймворков)
- Telegram WebApp SDK для авторизации
- Тёмная тема (как doorphone.html)
- Хостится в `hik-web/` через nginx

### Функционал

1. **Список пользователей** — карточки с ролью, правами-тогглами
2. **Генератор приглашений** — модальная форма → ссылка `t.me/<bot>?start=invite_<token>`
3. **Управление правами** — чекбоксы → PUT на изменение
4. **Лог действий** — последние 50 записей

### Авторизация

Telegram WebApp initData → `X-Telegram-InitData` заголовок → HMAC валидация на сервере.

## 5. Проверка прав

**Файл:** `hik-telegram-bot/app/database.py`

```python
async def check_permission(telegram_user_id: int, permission: str) -> bool:
    user = await get_user(telegram_user_id)
    if not user or not user["is_active"]:
        return False
    return bool(user.get(permission, False))
```

### Где проверять

| Эндпоинт | Право |
|----------|-------|
| POST /api/door/open | can_open_door |
| GET /api/camera/snapshot | can_view_video |
| WebSocket /ws/audio | can_talk |
| POST /api/admin/* | role == 'owner' |

## 7. Верификация

1. **Миграция**: запустить → проверить `GET /api/admin/users` → существующий пользователь имеет role=owner
2. **Приглашение**: создать → скопировать ссылку → перейти → пользователь зарегистрирован
3. **Права**: отключить can_open_door → попытка открыть дверь → 403
4. **Уведомления**: позвонить → все активные пользователи получают уведомление
5. **Веб-интерфейс**: открыть settings.html через Telegram → список пользователей виден
6. **Логирование**: выполнить действия → проверить audit_log
