# Компоненты

## Telegram Bot

Назначение:

- уведомления;
- команды;
- приглашения;
- быстрые действия.

Не содержит бизнес-логики.

---

## Telegram Mini App

Основной пользовательский интерфейс.

Через Mini App выполняются:

- просмотр видео;
- разговор;
- открытие двери;
- управление приглашениями;
- история;
- профиль;
- администрирование.

---

## Backend

Центральный компонент системы.

Отвечает за:

- авторизацию;
- права доступа;
- API;
- журнал событий;
- взаимодействие с камерой;
- взаимодействие с дверью.

---

## HCNetSDK

Используется исключительно для голосовой связи.

Видео через HCNetSDK не используется.

---

## go2rtc

Используется только для видеопотока.

Поддерживаются:

- WebRTC;
- HLS;
- MSE.

---

## Door Controller

Отдельный сервис открытия двери.

Backend не зависит от конкретного оборудования.

---

# Основные принципы

## Один вход в HCNetSDK

Используется одна авторизованная сессия.

Повторный вход не создаётся.

---

## VoiceSession

Во время разговора используется одна активная VoiceSession.

Она создаётся при начале разговора и освобождается после завершения.

---

## Видео

Для просмотра используется только канал **102 (Sub Stream)**.

Канал **101** зарезервирован и не используется приложением.

---

## Telegram

Telegram не является системой хранения данных.

Используется только для:

- уведомлений;
- команд;
- запуска Mini App.

---

## История

История хранится только в базе данных приложения.

---

## Аудит

Все административные действия записываются.

---

# Принцип развития

Любая новая функция должна:

- иметь проверку прав;
- иметь запись в журнал;
- иметь настройки (если применимо);
- соответствовать существующей архитектуре.

Изменение архитектурных решений допускается только после обновления документации.
