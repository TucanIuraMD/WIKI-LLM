# Database

## Назначение

База данных является основным хранилищем состояния системы.

В базе данных хранятся:

- пользователи;
- роли;
- права доступа;
- настройки;
- история;
- аудит;
- приглашения.

Telegram и камера не являются источниками данных.

---

# Основные сущности

## User

Пользователь системы.

Хранится:

- Telegram ID
- имя
- роль
- статус
- дата регистрации
- дата последнего входа

---

## Role

Определяет уровень доступа.

Примеры:

- Administrator
- User
- Guest

---

## Permission

Описание отдельных разрешений.

Например:

- open_door
- manage_users
- manage_settings
- view_history

Роль может содержать несколько разрешений.

---

## Invitation

Приглашение для доступа.

Содержит:

- владелец
- срок действия
- количество использований
- статус

---

## Event

История событий системы.

Примеры:

- открытие двери;
- вход пользователя;
- звонок;
- ошибка;
- изменение настроек.

---

## Audit Log

Журнал административных действий.

Фиксируются:

- пользователь;
- действие;
- время;
- результат;
- дополнительные данные.

---

## Settings

Настройки системы.

Например:

- параметры Telegram;
- параметры видео;
- параметры аудио;
- настройки двери;
- системные параметры.

---

Settings являются независимой сущностью.

---

# Принципы хранения

Все данные имеют единственный источник хранения.

Не допускается хранение состояния:

- в Telegram;
- в Mini App;
- в памяти Backend (кроме временных данных).

---

# История

История событий не удаляется автоматически.

При необходимости используется архивирование.

---

# Аудит

Все административные действия записываются.

Журнал аудита не должен изменяться пользователями.

---

# Ограничения

База данных используется только Backend.

Прямой доступ Mini App к базе отсутствует.

Все операции выполняются через API.

---

# Принципы развития

При добавлении новой сущности необходимо определить:

- связи с существующими сущностями;
- правила хранения;
- необходимость аудита;
- необходимость истории;
- необходимость настройки прав доступа.
