# Аудит проекта — 2026-08-19

> Полный read-only аудит: архитектура, качество кода, безопасность, тесты, риски развёртывания.
> Исходный код в ходе аудита не изменялся.

## 1. Архитектура

Система состоит из четырёх компонентов, оркестрируемых Docker Compose:

| Компонент | Технологии | Роль |
|-----------|-----------|------|
| `hik-talk` | FastAPI, HCNetSDK (ctypes), G.711 μ-law | Голосовая связь (PTT), эндпоинты `/talk`, `/ws/audio` |
| `hik-telegram-bot` | python-telegram-bot, FastAPI, aiosqlite | Telegram-бот, Mini App API, пользователи, приглашения, аудит |
| `hik-web` | nginx, статика (HTML/JS) | Фронтенд + обратный прокси, TLS (self-signed) |
| `go2rtc` | alexxit/go2rtc | Видеорелей (WebRTC/HLS/MSE), RTSP→камера |

Поток данных: камера Hikvision → go2rtc (видео) / HCNetSDK (голос) → FastAPI → nginx → браузер/Telegram.

## 2. Качество кода

### Найденные проблемы

- **Дублирование сервера.** `hik-talk/talk_server.py` (222 строки) и `hik-talk/app/main.py` (621 строка) — две версии одного сервера. Dockerfile запускает `app/main.py`; `talk_server.py` — устаревший дубль с захардкоженными дефолтами IP/порта.
- **Пустые модули-заглушки.** `hik-talk/app/audio.py`, `config.py`, `sdk.py`, `video.py` — 0 байт, но отслеживаются git'ом. Сбивают с толку при навигации.
- **CI lint падает.** `flake8 hik-talk/app/ --ignore=E501,W503,E402` завершается с ошибками: `F403/F405` (star-imports), `E302`, `E226`, `E305`, `W292`. CI job `lint` сейчас не прошёл бы.
- **Мусорный файл `=10.0`** (10 КБ) в корне — артефакт от некорректной shell-команды установки `Pillow>=10.0` (красная запись). Не игнорируется `.gitignore`.
- **Общее состояние:** глобальная мутабельная `next_send`, отсутствие типизации на стыках, смешение RU/EN комментариев.

### Что хорошо

- Чистое разделение аудио-кодеков, обработки изображений (`image_processor.py`) и SDK-обвязки.
- Понятная схема БД (users, houses, invites, audit_log, call_sessions, admin_sessions) с миграциями через `PRAGMA`.
- Корректная HMAC-проверка Telegram initData (5-минутное окно, `hmac.compare_digest`).
- Надёжная архитектура VoiceSession (очередь, retry/backoff при SDK error 29, переоткрытие канала).

### Критические уязвимости (требуют исправления)

- **🔴 `/api/door/open` — обход авторизации.** Если `telegram_user_id` отсутствует или пользователь не найден — запрос разрешается ("session-based access"). Дверь может открыть любой аноним. Кроме того, `telegram_user_id` берётся из тела запроса — клиент может подставить чужой ID и получить его права. Нет проверки initData/HMAC на этом эндпоинте.
- **🔴 CORS `allow_origins=["*"]`** с `allow_methods=["*"]` и `allow_headers=["*"]` — любой сайт в браузере может вызывать API (door open, admin).
- **🟠 Утечки данных без авторизации.** `/api/telegram/check` и `/api/telegram/user` отдают данные пользователей по любому `user_id` без аутентификации.
- **🟠 go2rtc API открыт через nginx `/api/`** без аутентификации — любой может управлять видеорелеем.
- **🟠 Приватный ключ TLS закоммичен**: `hik-web/certs/key.pem` (self-signed, но всё же).
- **🟠 Токены в URL**: session token (`?session=...`) и admin token (`settings.html?token=...`) попадают в историю браузера и логи nginx.
- **🟠 `/api/call/session`** игнорирует заголовок `X-Telegram-InitData`, который шлёт фронтенд; аутентификация — только по session token в query.
- **🟠 `/api/call/door-opened`** использует `get_call_session_raw` без проверки status/expiry.
- **🟠 nginx `sub_filter`** (`http://→https://`, `ws://→wss://`, `:1984→''`) — хрупкая замена строк в теле ответа, может портить контент.

### Прочее

- WebSocket `/talk` — без аутентификации вовсе.
- Документация (`docs/12_SECURITY.md`) описывает JWT-модель, фактически в коде JWT нет — используются самодельные токены сессий.
- Хардкод IP: `go2rtc.yaml` (`192.168.88.106`, webrtc candidate `192.168.80.21:8555`), `talk_server.py` (дефолт `192.168.80.25`).

## 5. Риски развёртывания

- **`hik-web/Dockerfile` сломан**: `COPY css /usr/share/nginx/html/css` и `COPY img /usr/share/nginx/html/img` — таких директорий в репозитории нет → `docker build ./hik-web` (и CI docker-build, и `docker compose up -d`) завершится ошибкой.
- **Нет нативных библиотек HCNetSDK** в репо (`.so` исключены `.gitignore`). Свежий clone + docker build даст контейнер без `libhcnet*`, и `cdll.LoadLibrary` упадёт при импорте. Тесты это маскируют моками.
- **Self-signed TLS** → предупреждения браузеров; `sub_filter` для смешанного контента — хрупкое решение.
- **go2rtc webrtc candidate** захардкожен на LAN-IP — за пределами сети не заработает.
- **`hik-talk` и `hik-telegram-bot`** в compose монтируют `.env`, но при его отсутствии сервисы стартуют с пустыми credentials (нет fail-fast).
