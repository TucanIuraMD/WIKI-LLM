Этот документ определяет правила, которым должен следовать ИИ при работе с проектом.

Перед внесением изменений необходимо ознакомиться с:

1. 00_Project.md
2. 03_ARCHITECTURE.md
3. 04_DECISIONS.md
4. 05_PROJECT_STATE.md

---

# Основные принципы

## Не менять архитектуру

Если задача может быть решена в рамках существующей архитектуры, необходимо использовать существующие компоненты.

Не создавать новую архитектуру без явной необходимости.

---

## Использовать существующие сервисы

Перед созданием нового класса, сервиса или модуля необходимо проверить, существует ли аналогичная функциональность.

Не дублировать код.

---

## Backend — единственная точка бизнес-логики

Вся проверка прав, принятие решений и взаимодействие между компонентами выполняются через Backend.

Не переносить бизнес-логику в Telegram Bot или Mini App.

---

## Telegram

Telegram используется только для:

- уведомлений;
- команд;
- запуска Mini App.

История и данные не хранятся в Telegram.

---

## Видео

Для просмотра видео используется только:

- Channel 102 (Sub Stream);
- go2rtc;
- WebRTC/HLS.

Не использовать Channel 101.

---

## Аудио

Для голосовой связи используется:

- HCNetSDK;
- VoiceSession;
- G.711 μ-law;
- Push-To-Talk.

Не создавать несколько одновременных VoiceSession.

---

## Авторизация

Все защищённые API должны проверять:

- токен;
- права пользователя;
- роль пользователя.

---

## Новые функции

При добавлении новой функции необходимо определить:

- нужны ли новые права доступа;
- требуется ли запись в журнал аудита;
- требуется ли обновление API;
- требуется ли обновление документации.

---

## Документирование

После изменения проекта необходимо обновить соответствующие документы.

Архитектурные изменения — 03_ARCHITECTURE.md

Новые решения — 04_DECISIONS.md

Текущее состояние — 05_PROJECT_STATE.md

Изменения API — 06_API.md

---

## Что запрещено

Не создавать:

- дублирующие сервисы;
- повторную авторизацию HCNetSDK;
- повторные VoiceSession;
- новый способ работы с видео;
- новую систему авторизации без необходимости.

---

## Перед написанием кода

Всегда выполнить следующий порядок действий:

1. Изучить существующую реализацию.
2. Найти место для интеграции.
3. Использовать существующие сервисы.
4. Только после этого писать код.

Предпочтение отдаётся расширению существующей архитектуры, а не созданию новых компонентов.
