# Development Rules

## Общие правила

- Не дублировать существующий код.
- Не изменять архитектуру без необходимости.
- Использовать существующие сервисы.
- Следовать принятым архитектурным решениям.

---

## Backend

- Вся бизнес-логика находится в Backend.
- Все API защищаются проверкой прав.
- Все изменения проходят через сервисный слой.

---

## Telegram

- Bot используется для уведомлений и команд.
- Mini App — основной пользовательский интерфейс.

---

## Видео

- Использовать только Channel 102.
- Видео передаётся только через go2rtc.
- Не использовать HCNetSDK для видео.

---

## Аудио

- Одна VoiceSession.
- Один вход в HCNetSDK.
- G.711 μ-law.
- Push-To-Talk.

---

## Документация

После изменения необходимо обновить:

- PROJECT_STATE.md
- DECISIONS.md (при необходимости)
- API.md (если изменилось API)
- CHANGELOG.md

---

## Перед коммитом

Проверить:

- сборку проекта;
- отсутствие ошибок;
- прохождение тестов;
- актуальность документации.

---

## Принципы

Приоритеты разработки:

1. Простота.
2. Надёжность.
3. Читаемость.
4. Расширяемость.
5. Обратная совместимость.
