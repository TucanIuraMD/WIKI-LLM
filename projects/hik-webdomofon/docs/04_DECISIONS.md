# Архитектурные решения

В этом документе фиксируются все важные архитектурные решения проекта.

---

# ADR-001

## Использование Telegram Mini App как основного интерфейса

**Статус**

Принято

**Причина**

Mini App предоставляет единый пользовательский интерфейс для Android, iOS и Web без необходимости разрабатывать отдельные приложения.

**Последствия**

- основной интерфейс находится в Mini App;
- Telegram Bot используется только для уведомлений и команд.

---

# ADR-002

## Использование HCNetSDK только для аудио

**Статус**

Принято

**Причина**

HCNetSDK обеспечивает стабильную двустороннюю голосовую связь.

Видео через SDK не используется.

**Последствия**

- голос — HCNetSDK;
- видео — go2rtc.

---

# ADR-003

## Использование go2rtc для видеопотока

**Статус**

Принято

**Причина**

go2rtc обеспечивает:

- WebRTC;
- HLS;
- MSE;
- низкую задержку.

---

# ADR-004

## Использование только канала 102

**Статус**

Принято

**Причина**

Sub Stream обеспечивает достаточное качество при значительно меньшей нагрузке.

Main Stream остаётся свободным.

**Последствия**

- приложение использует только Channel 102;
- Channel 101 не используется.

---

# ADR-005

## Один вход в HCNetSDK

**Статус**

Принято

**Причина**

Повторные подключения приводят к конфликтам Voice Talk.

Используется единая авторизованная сессия.

# ADR-006

## Одна активная VoiceSession

**Статус**

Принято

**Причина**

Камера поддерживает только одну голосовую сессию одновременно.

# ADR-007

## История хранится в базе данных

**Статус**

Принято

**Причина**

Telegram не предназначен для долговременного хранения истории.

---

# ADR-008

## Telegram используется только как транспорт

**Статус**

Принято

**Причина**

Telegram отвечает за:

- уведомления;
- запуск Mini App;
- быстрые действия.

Основная логика находится на сервере.

---

# ADR-009

## Все действия проходят через Backend

**Статус**

Принято

**Причина**

Backend является единственной точкой принятия решений.

Это позволяет централизованно реализовать:

- проверку прав;
- журналирование;
- аудит;
- бизнес-логику.

---

# ADR-010

## Любая новая функция должна быть интегрирована в существующую архитектуру

Перед добавлением новой возможности необходимо определить:

- нужны ли новые права;
- требуется ли запись в журнал;
- требуется ли запись в историю;
- нужны ли настройки;
- влияет ли изменение на API;
- необходимо ли обновить документацию.
