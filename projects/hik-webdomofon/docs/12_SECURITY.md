# Security

## Назначение

Документ описывает принципы обеспечения безопасности системы.

Все проверки безопасности выполняются Backend.

---

# Модель безопасности

Все компоненты взаимодействуют только через Backend.

```
User
   │
Telegram
   │
Mini App
   │
JWT
   │
Backend
   │
───────────────
│ Авторизация │
│ Проверка    │
│ Аудит       │
│ API         │
───────────────
   │
   ▼
Camera / Door / Database
```

---

# Аутентификация

Используется авторизация через Telegram.

Backend проверяет:

- Telegram InitData;
- подпись;
- срок действия данных.

После успешной проверки создаётся пользовательская сессия.

---

# JWT

После авторизации Backend выдаёт JWT.

JWT используется для:

- REST API;
- WebSocket;
- административной панели.

Недействительный токен приводит к отказу в доступе.

---

# Авторизация

После проверки личности определяется роль пользователя.

Права доступа проверяются перед выполнением каждой операции.

Например:

- открыть дверь;
- изменить настройки;
- создать пользователя;
- удалить приглашение.

---

# Роли

Минимальный набор ролей:

- Administrator
- User
- Guest

Каждая роль обладает собственным набором разрешений.

---

# Защита API

Все защищённые endpoints обязаны:

- проверять JWT;
- проверять права;
- валидировать входные данные;
- возвращать корректные ошибки.

Backend никогда не доверяет данным клиента.

---

# WebSocket

WebSocket требует авторизации.

После установки соединения Backend:

- проверяет токен;
- проверяет права;
- создаёт пользовательский контекст.

При завершении соединения все ресурсы освобождаются.

---

# Защита административной панели

Доступ разрешён только администраторам.

Backend дополнительно проверяет:

- роль;
- права;
- срок действия токена.

---

# Хранение секретов

Секретные данные не должны храниться в исходном коде.

Используются:

- переменные окружения;
- конфигурационные файлы;
- защищённое хранилище (при необходимости).

---

# Логирование

Не допускается запись:

- паролей;
- JWT;
- секретных ключей;
- токенов Telegram;
- конфиденциальных данных пользователей.

---

# Аудит

Все административные действия могут фиксироваться.

Примеры:

- вход администратора;
- изменение настроек;
- управление пользователями;
- открытие двери.

---

# Ограничение доступа

Backend является единственной точкой доступа к:

- базе данных;
- камере;
- контроллеру двери.

Прямой доступ клиента запрещён.

---

# Обработка ошибок

Сообщения об ошибках не должны раскрывать:

- внутреннюю структуру системы;
- конфигурацию;
- стек вызовов;
- секретные данные.

---

# Принципы разработки

При добавлении новой функции необходимо:

- определить необходимые права доступа;
- добавить проверку авторизации;
- оценить необходимость записи в аудит;
- проверить обработку ошибок;
- исключить утечку конфиденциальной информации.
