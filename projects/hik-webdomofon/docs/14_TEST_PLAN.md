# Test Plan

## Назначение

Документ определяет перечень тестов, необходимых для проверки работоспособности системы.

Все изменения должны проверяться перед выпуском новой версии.

---

# Общие требования

Перед тестированием необходимо:

- запустить Backend;
- убедиться в доступности камеры;
- проверить работу go2rtc;
- проверить подключение к базе данных;
- убедиться в доступности Telegram Bot.

---

# Функциональные тесты

## Авторизация

Проверить:

- вход через Telegram;
- получение JWT;
- обновление токена (если реализовано);
- завершение сессии.

---

## Видео

Проверить:

- получение конфигурации потока;
- подключение по WebRTC;
- переключение на HLS (если необходимо);
- восстановление после разрыва соединения.

---

## Голосовая связь

Проверить:

- запуск разговора;
- передачу аудио;
- приём аудио;
- завершение разговора;
- повторное подключение.

---

## Открытие двери

Проверить:

- успешное открытие;
- отказ при отсутствии прав;
- обработку ошибки контроллера.

---

## Telegram

Проверить:

- команды бота;
- уведомления;
- запуск Mini App;
- обработку ошибок.

---

## Администрирование

Проверить:

- вход администратора;
- управление пользователями;
- изменение настроек;
- проверку прав.

---

# Интеграционные тесты

Проверить взаимодействие:

- Backend ↔ HCNetSDK
- Backend ↔ go2rtc
- Backend ↔ Telegram
- Backend ↔ Database
- Backend ↔ Door Controller

---

# Проверка безопасности

Проверить:

- неверный JWT;
- отсутствие токена;
- недостаточные права;
- доступ к административным API;
- WebSocket без авторизации.

---

# Проверка производительности

Проверить:

- длительную работу системы;
- многократное открытие видеопотока;
- многократное открытие голосовой связи;
- повторные подключения WebSocket.

---

# Проверка восстановления

Проверить поведение после:

- перезапуска Backend;
- отключения камеры;
- отключения go2rtc;
- потери сети;
- повторного подключения.

---

# Регрессионное тестирование

После каждого изменения необходимо проверить:

- авторизацию;
- видео;
- голосовую связь;
- открытие двери;
- Telegram;
- административную панель.

---

# Критерии готовности

Версия считается готовой к выпуску, если:

- отсутствуют критические ошибки;
- все обязательные тесты пройдены;
- документация обновлена;
- известные ограничения задокументированы.

---

# Принципы

Новые функции должны сопровождаться новыми тестами.

Исправление ошибки должно сопровождаться проверкой, исключающей её повторное появление.
