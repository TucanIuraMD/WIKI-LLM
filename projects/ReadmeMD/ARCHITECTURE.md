# ReadmeMD — архитектура

Документ описывает **фактическую** реализацию после перехода на внешний
Obsidian Vault.

## Принцип

ReadmeMD — это тонкий интерфейс поверх существующего Obsidian Vault.

```
┌─────────────────────────────┐        ┌──────────────────────────────────┐
│  Браузер (templates/,       │  HTTP  │  Flask backend (app.py)          │
│  static/js/app.js)          │ ─────► │                                  │
│  - дерево                   │        │  - safe_vault_path() — контроль  │
│  - рендер Markdown (client) │        │    доступа внутри VAULT_DIR      │
│  - Monaco-редактор          │        │  - только чтение/запись .md      │
└─────────────────────────────┘        └───────────────┬──────────────────┘
                                                        │  прямое обращение
                                                        ▼  к файлам (без копий)
                                            ┌──────────────────────────────┐
                                            │  Внешний Vault               │
                                            │  /opt/ai-stack/obsidian-vault│
                                            │  (путь задаётся в .env       │
                                            │  через VAULT_DIR)            │
                                            └──────────────────────────────┘
```

Ключевое отличие от старой версии: раньше приложение владело собственным
хранилищем `docs/` и копировало/сохраняло файлы туда. Теперь приложение
работает **непосредственно** с каталогом Vault и не создаёт никаких копий.

## Конфигурация

- Конфигурация загружается из `.env` (python-dotenv) в начале `app.py`.
- `VAULT_DIR` — путь к Vault, единственная точка определения хранилища.
  Не зашит в бизнес-логику. `load_dotenv()` не перезаписывает уже заданные
  переменные окружения, поэтому `VAULT_DIR` можно переопределить из окружения.
- `HOST` / `PORT` / `DEBUG` используются при запуске `python app.py`.

## Безопасность путей (`safe_vault_path`)

Входная точка для всех операций с путями — `safe_vault_path(rel_path)`:

1. Отбрасываются: пустые пути, NUL-байты, обратные слэши (`\` → `/`),
   абсолютные пути (`Path.is_absolute()`).
2. `os.path.normpath()` нормализует `..`; если после нормализации путь всё ещё
   содержит выход наружу (`../`, `..`, `/../`) — отклоняется (400).
3. Итоговый путь резолвится через `resolve()` (раскрывает симлинки) и
   проверяется `is_within_vault()`: путь обязан находиться внутри
   `VAULT_DIR` (равен ему или является потомком).
4. Если требуется существование (`must_exist=True`) и путь не существует —
   404.

Дополнительно:

- **Симлинки-файлы за пределы Vault**: `resolve()` вернёт внешний путь →
  `is_within_vault()` → отклонение. Такие файлы не попадают в дерево,
  поиск и граф (`_safe_walk`, `build_tree`).
- **Симлинки-каталоги**: не обходятся вовсе (защита от циклов и выхода
  за пределы).
- **Запись**: разрешена только в `.md`-файлы; родительский каталог проверяется
  `is_within_vault()` перед `mkdir`/записью.
- **Upload**: имя файла очищается `os.path.basename()` (без компонентов пути),
  допустимы только `.md`; целевой каталог из `folder` проходит
  `safe_vault_path()`.

## Компоненты backend (app.py)

| Функция/роут | Назначение |
|---|---|
| `safe_vault_path`, `is_within_vault` | контроль доступа к путям |
| `_safe_walk`, `iter_all_docs` | безопасный обход Vault (без симлинк-каталогов, без скрытых файлов) |
| `build_tree`, `/api/tree` | дерево каталогов Vault |
| `read_doc`, `parse_frontmatter` | чтение документа + YAML front matter |
| `/api/page` GET/PUT/DELETE | чтение / сохранение / удаление документа |
| `/api/search` | полнотекстовый поиск по заголовкам и содержимому |
| `/api/graph` | граф связей по `[[wikilinks]]` |
| `/api/upload` | загрузка `.md` файлов |
| `/api/folder-icon` | метаданные иконок папок (`.folder.json` внутри Vault) |
| `build_title_index`, `resolve_wikilink` | резолвинг `[[wikilinks]]` → пути |

## Компоненты frontend

- `templates/index.html` — одностраничный интерфейс.
- `static/js/app.js` — vanilla JS: загрузка дерева, рендер Markdown
  (markdown-it + highlight.js + Mermaid + KaTeX), wikilinks, граф
  (vis-network), Monaco-редактор с автосохранением, поиск, upload.
- `static/css/style.css` — стили (тёмная/светлая тема).

Замечание: рендер Markdown выполняется на клиенте; сервер отдаёт «сырой»
текст. Сохранение идёт через `PUT /api/page/<path>` целиком в Vault.

## История версий

Старая система `.versions/` (снимки файлов + diff) **удалена из кода и UI**.
Обоснование:

- После перехода на внешний Vault приложение не должно вести собственное
  хранилище копий — `.versions/` создавало дубликаты документов.
- Планируемый механизм истории — Git (здесь не реализуется на этом этапе).
